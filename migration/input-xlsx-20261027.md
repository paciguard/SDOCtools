# XLSX input project format

The owner supplied `Referrings/CFL资料工具输入模板.xlsx` on 2026-10-27. This reference is preserved byte for byte. Desktop Excel rejected the supplied file and its initial NPOI project copy. Isolated checks confirmed that removing its unused legacy defined names makes it open normally; removing only invalid name characters or zero-index references was insufficient. `Resources/Workbooks/Input.xlsx` is a derived copy with those unused names removed. Names needed by cell/validation formulas or print setup are retained. Every package part except the workbook name metadata remains byte-identical, including sheet XML, styles, rich-text strings, dropdowns and print settings. `input-xlsx-20261027.json` records both SHA-256 hashes and the removed names. The internal model remains `Resources/Workbooks/ZTools.xls`, preserving the supplied lookup tables and calculation rules.

New Windows and mobile projects use genuine XLSX packages, containing only `input`. The original worksheet layout, local dropdowns and print settings come from the new template. Sec-List/PID/Utility values, results and print options keep the same compressed state version 2, stored in OOXML custom document properties. XLS imports read the corresponding HPSF properties, preserving existing overrides.

A full NPOI XSSF round trip also rewrote legacy drawing/control XML into a package Excel could not reopen. Public saves therefore preserve the template package and replace only input cells/layout, shared strings/styles and the application property parts. Legacy drawings, controls, links, print settings and other parts retain their original bytes. A private package experiment verified native Excel opening before adopting this save path.

Windows accepts XLSX/XLS in its file picker and converts legacy workbooks to a separate input-only XLSX copy. Existing mobile XLS projects migrate beside their original file, which is retained. Mobile imports/exports use XLSX. Calculation staging preserves the actual project filename/extension so neither cancellation nor successful publication swaps file formats incorrectly. Windows Excel automation continues to use a private internal XLS working model; manual editing opens the public XLSX.

The historical XLS input template and previous migration record are retained for traceability and compatibility tests. No original workbook or business database is converted or replaced.
